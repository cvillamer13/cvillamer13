DevOps project: automated delivery

A GitOps pipeline that carries a code change from a feature branch to a running, monitored application, with no manual deploy steps.

GitHub / GitLabDockerKubernetesHelmArgo CDCI/CDPrometheusLokiTempoGrafana

  1. Push to a feature branch

    Frontend, backend or database changes are committed to a feature branch on GitHub or GitLab.

  2. Open a merge request

    The merge request into main is the review step, and merging it is what starts the pipeline.

  3. CI builds and containerizes

    When main updates, the CI pipeline builds the service and packages it as a Docker image.

  4. Push to a registry

    The image is published to Docker Hub or the GitLab container registry under a build-specific tag.

  5. Update the manifest repo

    CI automatically edits the image tag in a separate manifest repository, the single source of truth for what should be running.

  6. Argo CD syncs

    Argo CD notices the manifest change and updates the Helm release to match, so deployment follows Git instead of manual commands.

  7. Kubernetes rolls out

    Helm deploys the new image to the Kubernetes cluster and the application runs the updated version.

  8. Observe everything

    Prometheus collects metrics, Loki gathers logs and Tempo records traces. Grafana brings all three together on dashboards to monitor the system.
